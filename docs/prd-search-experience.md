# 搜索体验增强（历史 / 热门 / 联想）— PRD

## 1. 背景与目标

**观察到的问题：**
搜索页目前只有一个输入框：用户必须完整、准确地输入菜名才能发起搜索。空页面没有任何提示，输入过程中也没有补全，冷启动门槛高；用户每次进入都要重新输入，历史关键词无法复用。一旦输错或搜不到，页面只显示"没有找到"，没有继续尝试的路径。

**目标用户：**
"大概想吃什么、但说不准菜名"的普通用户——例如想吃"肉"、想找"快手菜"、或想重复搜索昨天看过的菜。

**产品决策：**
在搜索页补齐三件事：**搜索历史**（本地缓存，复用上次的搜索）、**热门搜索**（降低冷启动门槛）、**输入联想**（边输边补全）。三者点击后都直接发起搜索，形成"提示 → 点选 → 结果"的短路径。

**预期结果：**
- 用户进入搜索页即有可点的关键词，不必凭空回忆完整菜名；
- 输入 1～2 个字符即可看到候选菜名并直接点选；
- 搜索失败后仍有"换个关键词试试"的出口，而不是停在空结果页。

---

## 2. 范围

**P0（本次实现）：**
- 搜索历史：本地存储、去重、最新在前、最多 10 条、支持一键清空
- 热门搜索：打开搜索页即展示，点击直接搜索
- 输入联想：输入时展示匹配的菜名/历史词/热门词，点击直接搜索，命中片段高亮

**P1（本次一并包含）：**
- 输入框一键清空，清空后回到历史/热门面板
- 无结果空态提供热门词作为再试入口
- 联想请求失败时静默降级为本地词匹配，不打断输入

**明确排除：**
- 不做搜索结果的排序、筛选、分类 tab
- 不做搜索埋点上报、不做跨设备/跨账号同步
- 不新增后端接口；联想与热门词均复用现有接口
- 不改动分类页、首页的搜索入口样式

---

## 3. 核心流程与交互

```
进入搜索页
    ↓
┌─────────────────────────────┐
│ 搜索栏（自动聚焦，输入框为空） │
├─────────────────────────────┤
│ 搜索历史（有则显示，可清空）   │
│ 热门搜索（胶囊词，可点击）     │
└─────────────────────────────┘
    │ 输入字符
    ↓
联想列表（历史/热门本地命中 + 服务端菜名补全，防抖 300ms）
    │ 点击联想项 / 点击词 / 回车 / 点"搜索"
    ↓
写入搜索历史 → 收起键盘与联想 → 结果列表
    │
    ├─ 有结果：继续上拉分页
    └─ 无结果：提示 + 热门词再试入口
```

**状态互斥规则：** 历史/热门面板、联想列表、搜索结果三者同一时间只展示其一，避免内容叠加。

## 4. 功能需求

### FR-01：搜索历史

**用途：** 让用户复用最近的搜索，减少重复输入。

**存储规则：**

| 项目 | 规则 |
|------|------|
| 存储位置 | 小程序本地缓存，key：`search_history` |
| 数据结构 | 字符串数组，按最近搜索时间倒序 |
| 写入时机 | 任意一次真正发起搜索时：点击搜索按钮、键盘回车、点击历史词、点击热门词、点击联想项、从分类页带词跳入 |
| 去重 | 写入前先移除同名项，再插入到数组首位 |
| 容量 | 最多 10 条，超出丢弃最旧一条 |
| 空值 | 写入前 `trim`，空字符串不写入 |
| 异常容错 | 缓存读取失败或数据不是数组时按空数组处理，不阻塞页面 |

**交互规则：**
- 历史区标题右侧提供「清空」，点击后二次确认（`wx.showModal`），确认后清空本地缓存并隐藏历史区
- 点击任意历史词，直接以该词发起搜索
- 无历史记录时，历史区整体隐藏，仅展示热门搜索

---

### FR-02：热门搜索

**用途：** 给"不知道该搜什么"的用户一个可直接点的起点。

**数据来源：**
- 优先取现有 `/api/recipe.lists`（首页「热门菜谱」同源）返回的前 8 个菜名，去重后展示
- 请求失败或返回为空时，降级为内置默认词库：`红烧肉、宫保鸡丁、鱼香肉丝、水煮鱼、西红柿炒鸡蛋、清蒸鲈鱼、排骨、牛肉`（均为实测可搜到结果的菜名）
- 热门词请求为静默请求，失败不弹 toast

**展示规则：**
- 胶囊样式横向换行排列
- 前 3 个词前置序号 `1 / 2 / 3`，用于强化"热门"感知
- 点击任意热门词，直接以该词发起搜索

---

### FR-03：输入联想（Autocomplete）

**用途：** 用户只输入部分字符时，直接给出可点的完整候选。

**触发与更新：**
- 输入框有非空内容且处于聚焦状态时展示联想列表
- 本地联想：从搜索历史 + 热门词中筛选包含输入内容的词，立即展示（无网络延迟）
- 服务端联想：输入后防抖 300ms，调用现有 `/api/recipe.search`（`name=输入内容`），取返回菜名作为候选
- 合并规则：本地命中在前、服务端菜名在后，按文本去重，最多展示 8 条
- 服务端结果需再次校验"候选文本包含输入内容"，过滤后端模糊匹配到的无关项

**展示规则：**
- 每行：搜索图标 + 候选文本
- 命中的输入片段用主色加粗高亮（只高亮首次命中位置）
- 无候选时展示"暂无联想，直接搜索试试"；请求进行中展示"正在联想…"

**交互规则：**
- 点击任意候选行，以该候选完整文本发起搜索
- 输入框失焦后延迟 150ms 收起联想列表（保证点击候选能先被响应）
- 已发起搜索后再次点击输入框，重新展示联想列表

**性能与正确性：**
- 防抖 300ms，避免逐字符打请求
- 每次请求携带递增序号，返回时若序号已过期或输入内容已变化，直接丢弃该响应，防止旧结果覆盖新输入

---

### FR-04：输入区与页面状态

**用途：** 让三种状态之间的切换清晰、不闪烁。

| 元素/状态 | 规则 |
|-----------|------|
| 输入框 | 进入页面（无带词）自动聚焦；`maxlength=30`；`confirm-type=search` |
| 清空按钮 | 输入框有内容时显示；点击清空输入、结果与联想，回到历史/热门面板 |
| 搜索按钮 | 内容为空时 toast「请输入搜索内容」，不发起请求，不写历史 |
| 发起搜索 | 收起键盘、隐藏联想、记录历史、清空旧结果并进入 loading |
| 结果加载 | 首次加载无数据时展示"正在搜索…"，避免白屏 |
| 上拉分页 | 保持现有行为：未结束且不在加载中时请求下一页 |
| 下拉刷新 | 仅在已发起过搜索时重新请求第一页 |
| 空结果 | 展示"没有找到「关键词」相关的菜谱" + "换个关键词试试" + 热门词胶囊 |
| 请求竞态 | 新搜索会使旧请求失效，旧响应不得覆盖新结果 |

**带词进入：** 分类页语音/文字搜索通过 `?name=xxx` 跳入本页时，自动以该词搜索并写入历史，不自动弹键盘。

---

### FR-05：视觉规范

| 元素 | 样式 |
|------|------|
| 搜索栏 | 沿用现有圆角灰底搜索栏，白底吸顶，高度 76rpx |
| 清空按钮 | 40rpx 圆形灰底白字「×」 |
| 面板 | 白底，标题 28rpx 加粗；「清空」为 24rpx 次级文本色 |
| 历史词胶囊 | 灰底 `#F2F3F5`，文字 `var(--text)`，圆角 32rpx，字号 26rpx |
| 热门词胶囊 | 浅橙底 `var(--primary-light)`，文字 `var(--primary-dark)`，前 3 名带序号 |
| 联想行 | 白底、行高约 96rpx、1rpx 分割线，点击态浅灰 |
| 高亮 | `var(--primary-dark)` + 700 字重 |
| 空态 | 沿用全局 `.empty`，补充居中热门词胶囊作为行动入口 |

所有文本对比度遵循现有高对比度主题（主文本 `#1A1A1A`，次级 `#54565B`）。

## 5. 共享规则与边界条件

- **历史与热门重复：** 允许同一词同时出现在历史与热门中；两个区域独立展示，点击行为一致。
- **输入空格：** 保存与搜索均先 `trim`；仅空格视为空输入。
- **缓存异常：** `getStorageSync / setStorageSync` 均 try/catch，缓存不可用时功能降级为"本次会话内无历史"，不影响搜索本身。
- **联想接口失败：** 不弹错误提示，保留本地历史/热门命中结果；用户仍可手动点搜索。
- **热门接口失败：** 静默保留默认词库，不出现空白面板。
- **长关键词：** 输入框限制 30 字符，避免超长请求与胶囊溢出。
- **返回键：** 页面返回不改变历史数据。

## 6. 验收清单

- [ ] 首次进入搜索页：输入框聚焦，展示热门搜索；无历史时不显示历史区
- [ ] 搜索任意词后返回搜索页：该词出现在历史首位；重复搜索不产生重复项；超过 10 条时最旧一条被移除
- [ ] 点击历史词 / 热门词 / 联想项 / 键盘回车 / 搜索按钮，均能发起搜索并写入历史
- [ ] 输入 1～2 个字符：本地命中即时出现；约 300ms 后服务端菜名补全；命中片段高亮
- [ ] 连续快速输入时，不会出现旧联想结果覆盖新输入
- [ ] 点击清空：输入框、结果、联想全部清空，回到历史/热门面板
- [ ] 无结果时空态展示热门词，点击可再次搜索
- [ ] 断网状态下输入：联想降级为本地命中，不弹重复错误提示；历史与热门可正常点击
- [ ] 上拉分页、下拉刷新行为与改造前一致

## 7. 开放问题

| 问题 | 影响 | 当前处理 |
|------|------|----------|
| 后端暂无热门搜索词接口（`/api/recipe.hot` 返回 404） | 热门词的"搜索热度"语义无法真实还原 | [Assumption] 暂以热门菜谱名作为推荐词，接口需求见 [api-search-enhancement.md](./api-search-enhancement.md) |
| 搜索联想复用 `recipe.search`，单次返回整页数据 | 每次联想有一定数据开销 | 已做 300ms 防抖 + 最多取 8 条展示；轻量联想接口需求见 [api-search-enhancement.md](./api-search-enhancement.md) |
| 是否需要单条历史删除/长按删除 | 影响历史区交互复杂度 | 本次只做一键清空，单条删除留作 P2 |
| 是否需要记录搜索埋点 | 影响后续热门词运营与效果评估 | 本次不做，留作 P2 |
